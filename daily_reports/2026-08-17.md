### 2. 跑通 RoboCasa365 数据与环境语义

- 固定主任务为 Atomic `TurnOffSinkFaucet`，使用前 100 个 human demonstration，共
  11,608 frames。
- 梳理数据字段、相机输入、state/action 维度、参考系和控制器语义；确认本实验属于
  `EEF + Delta` 控制。
- 将原始 16D state 中的 EEF quaternion 转为 continuous rotation 6D，得到 20D state；
  12D RoboCasa action 保持不变。
- 实现训练数据和 RoboCasa rollout 共用的 rotation 6D adapter，避免训练/评测表示不一致。
- 建立数据、LeRobot 源码、RoboCasa source/assets、Hugging Face 权重和 tokenizer 的容器本地
  SSD cache，避免 NAS 位于训练热路径。

### 3. 建立统一训练与评测闭环

- 实现通用 launcher，可按实验配置启动训练、每 2,000 steps 做 5-episode 小评测、保存
  checkpoint，并在训练结束后自动做 50-episode 正式评测。
- 接入 TensorBoard，记录训练 loss、gradient norm、learning rate、评测 reward 和 success rate。
- 增加 GPU/Python/package/policy 来源 preflight、实际命令快照、有效配置快照和训练代码快照，
  提高实验可复现性。
- 修正训练和评测命令快照末尾多余空格的问题。

### 4. 固定三套 baseline

三套实验统一使用 20,000 steps、batch size 32、每 2,000 steps 保存并做 5-episode 小评测，
训练结束后做 50-episode 正式评测。

| Policy | 关键设置 | 训练起点 |
| --- | --- | --- |
| Diffusion Policy | `n_obs_steps=2`、`horizon=64`、`n_action_steps=32`、`drop_n_last_frames=7` | ResNet18 ImageNet 初始化，其余从头训练 |
| ACT | `chunk_size=64`、`n_action_steps=32`、VAE、`kl_weight=10` | ResNet18 ImageNet 初始化，其余从头训练 |
| Pi0.5 | `chunk_size=50`、`n_action_steps=10`、gradient checkpointing、full fine-tuning | 官方通用 `lerobot/pi05_base` |

此前将 DP/ACT 改为 batch 8、100k steps 的判断已撤销，恢复为 batch 32、20k steps；ACT 的
action chunk 同时从原始 100/100 调整为 64/32，缩短 open-loop 执行时间。

### 5. 加固 Pi0.5 预训练权重加载

- 将起点从 LIBERO-specific checkpoint 改为官方通用 `lerobot/pi05_base`。
- 固定 revision `b211f3d44c36b6acfcf7ae94a64e8e96f75a64ba` 和
  `model.safetensors` 大小 14,467,165,872 bytes。
- 启动时校验 Hugging Face cache identity、revision、config、pre/postprocessor 和权重文件大小。
- 将 `PI05Policy.from_pretrained()` 改为 fail-closed：权重解析、key remap 或 strict
  `state_dict` 加载失败时直接终止，禁止静默回退到随机初始化的 4B 模型。

### 6. 解决 DSW tmux 启动冲突

- 复现并定位 `server exited unexpectedly`：阿里云 DSW Web Terminal 管理的默认 tmux
  server 注入了平台 `TMUX_BINARY` / `TMUX_CONFIG`，与系统 tmux 创建 detached session
  的流程冲突；独立 socket 测试正常，确认问题与训练配置和 GPU 无关。
- 训练和独立评测 launcher 现在为每个实验创建同名、忽略平台配置的独立 tmux socket。
- status/stop 脚本同时兼容新独立 socket 和修复前已启动在默认 socket 中的 session。
- 先建立 persistent pane 再启动训练命令；即使 preflight 立即失败，也会保留 stderr 和退出码。

### 7. 定位 Pi0.5 首次启动参数错误

- Pi0.5 完成全部本地缓存和 Python/GPU preflight 后，首次启动在 LeRobot CLI 解析阶段以
  exit code 2 结束，尚未加载权重或执行 training step。
- 根因是 pretrained `--policy.path=...` 与 `--policy.discover_packages_path=...` 同时传入时，
  LeRobot 会把 discovery 参数再次作为 checkpoint config override，最终报
  `unrecognized arguments: --discover_packages_path=...`。
- 已将 discovery 参数限制在 `--policy.type` 的从头训练路径；Pi0.5 训练和所有 checkpoint
  eval 的 `--policy.path` 路径不再传 discovery 参数。
